3) Теория по атрибутам (кратко)
- value: начальное значение поля, отправляется при сабмите.
- placeholder: подсказка до ввода; не заменяет видимую метку label.
- minlength/maxlength: ограничения длины содержимого (клиентская проверка).
- size: видимая ширина в символах; для вёрстки предпочтительнее CSS.
- required: встроенная HTML5-валидация обязательного поля.
- pattern: регулярное выражение для валидации; добавляйте title для объяснения формата.
- readonly: поле нельзя редактировать, но оно отправляется с формой.
- disabled: поле недоступно и НЕ отправляется.
- autocomplete: управление автозаполнением браузера (например, name, email, tel, off).
- autofocus: автофокус при загрузке (лучше не более одного на странице).
- inputmode: подсказка для экранной клавиатуры (email, tel и т. п.); дополняет type.

Специализированные типы
- email: встроенная проверка формата + удобная клавиатура на мобильных.
- url: встроенная проверка валидности URL.
- tel: ввод телефона; для жёсткого формата используйте pattern.
- search: семантическое поле поиска; может иметь особый UI в браузере.

Textarea
- rows/cols: видимые размеры; ширину обычно задают через CSS.
- wrap: soft (по умолчанию) или hard (вставляет переносы строк при отправке).
- resize (CSS): управление возможностью изменения размера (например, resize: vertical;).

ARIA (доступность)
- aria-label: имя для скринридеров при отсутствии видимого label; предпочтительнее использовать связку label for/id.
- aria-required: сообщает вспомогательным технологиям, что поле обязательное; часто достаточно required, но aria-required повышает ясность.
- aria-describedby: связывает поле с подсказкой/ошибкой по id, чтобы скринридер её озвучивал.
- Логический порядок табуляции обеспечивается порядком элементов в DOM; избегайте tabindex>0; tabindex=0 используйте только для кастомных фокусируемых элементов.

3) Подробные объяснения атрибутов и элементов

А) Поля ввода (input type="text") и общие атрибуты
- value: задаёт начальное значение. Если пользователь изменит значение, при отправке формы уйдёт новое.
- placeholder: светло-серый текст-подсказка. Не заменяет <label>. На слабой контрастности может быть плохо читаем.
- minlength/maxlength: проверка минимальной/максимальной длины строки на стороне браузера. Работает только при наличии валидации браузера (без novalidate). Сервер обязан повторно проверять длину.
- size: ширина поля в символах. Лучше управлять шириной через CSS (width), так как size влияет не на макет, а на число видимых символов.
- required: помечает поле обязательным. Браузер не отправит форму без значения (если не отключена валидация атрибутом novalidate на <form>). Доступнее дублировать визуально «*» и пояснением.
- pattern: регулярное выражение для проверки значения. Рекомендуется указывать якоря ^ и $, чтобы проверять всю строку: например ^[0-9]{6}$. Добавляйте title — браузер покажет его как подсказку при ошибке.
- readonly: поле только для чтения. Значение отправится, но пользователь не может его менять. Полезно для расчётных или предзаполненных полей.
- disabled: поле недоступно и не отправляется на сервер. Также не попадает в фокус по Tab. Осторожно: можно потерять данные при ожидании отправки.
- autocomplete: управляет автозаполнением (например: off, name, given-name, family-name, email, tel, address-line1 и др.). Улучшает UX и доступность.
- autofocus: автоматически ставит фокус на поле при загрузке страницы. Используйте только один раз на странице, иначе управление фокусом станет непредсказуемым.
- inputmode: подсказка для экранной клавиатуры на мобильных (text, numeric, decimal, tel, email, url). Не заменяет type, а дополняет.

Б) Специализированные типы input
- type="email": базовая проверка формата email (минимальная). Не гарантирует существование адреса. Для строгой проверки используйте сервер.
- type="url": базовая проверка валидности URL. Добавляйте полный протокол (https://), иначе может считаться невалидным.
- type="tel": нет встроенной проверки формата; используйте pattern для нужной маски. На мобильных даёт удобную клавиатуру.
- type="search": семантика «поиск», в некоторых браузерах добавляет «очистить» и иные фишки. По поведению близок к text.

В) <textarea>
- rows, cols: задают видимую высоту/ширину в символах. Для ширины предпочтительнее CSS (width/max-width).
- wrap: soft (по умолчанию) не вставляет переводы строк при отправке; hard — вставляет реальные переносы (\n) в отправляемые данные. Учитывайте на сервере.
- resize (CSS): управление возможностью изменения размера: none | vertical | horizontal | both. Например, textarea { resize: vertical; }.

Г) Доступность (ARIA) и подсказки
- label for/id: основной способ связать подпись и поле. Скринридеры объявляют имя поля по <label>.
- aria-label: альтернативное имя, когда нет видимой подписи. Используйте с осторожностью; предпочтителен label.
- aria-labelledby: можно сослаться на существующий элемент-заголовок по id, чтобы задать имя поля/группы.
- aria-describedby: свяжите поле с подсказкой/ошибкой (например, <small id="hint">). Скринридер озвучит описание после имени поля.
- aria-required="true": дублирует required для вспомогательных технологий. Не обязателен, но повышает ясность.
- aria-invalid="true": помечает поле как невалидное (особенно полезно при кастомной валидации JS, когда HTML5 не сработал).
- Регионы ошибок/статусов: используйте role="alert" или aria-live="assertive|polite" для динамических сообщений об ошибках/успехе.

Д) Клавиатура и порядок табуляции
- Порядок фокуса определяется порядком элементов в DOM. Старайтесь, чтобы визуальный и DOM-порядок совпадали.
- Избегайте tabindex>0: это ломает естественный порядок Tab и усложняет поддержку. Для кастомных элементов достаточно tabindex="0" (включить в поток фокуса).
- Кнопки и ссылки должны быть нативными (<button>, <a href>), а не <div> с обработчиком — так обеспечивается доступность и фокусируемость «из коробки».

Е) Лучшие практики
- Не полагайтесь только на HTML5-валидацию — сервер всегда должен проверять данные.
- Короткие, понятные сообщения об ошибках рядом с полем; свяжите их через aria-describedby.
- Не используйте placeholder вместо label: placeholder пропадает при вводе и ухудшает доступность.
- Для масок телефона используйте pattern и/или JS-маску, но отправляйте на сервер нормализованное значение.

4) Полное описание страницы forms.html (по разделам)

Заголовок и вводный текст
- Заголовок: «Витрина форм». Кратко объясняет, что ниже — примеры элементов форм, атрибутов и приёмов доступности.

Текстовые поля (type="text")
- Одна демонстрационная форма (с csrf) с novalidate, чтобы браузер не блокировал отправку и не мешал показу примеров.
- Примеры полей и что они показывают:
  • value — предустановленное значение.
  • placeholder — текст-подсказка до ввода.
  • minlength/maxlength — ограничение длины значения.
  • size — видимая ширина поля в символах (рекомендуется CSS вместо size для реальной вёрстки).
  • required + aria-required — обязательность поля (и подсказка для скринридеров).
  • pattern + title — проверка по регулярному выражению (пример: только латиница A–Z).
  • readonly — поле нельзя редактировать, но значение отправляется.
  • disabled — поле недоступно и не отправляется.
  • autocomplete — демонстрация токена name.
  • autofocus — автоматический фокус при загрузке.

Специализированные поля
- email — базовая проверка email.
- url — базовая проверка URL.
- tel — пример с pattern и inputmode (мобильная клавиатура для телефона).
- search — семантика поля поиска (placeholder «Поиск…»).
- Дополнительно добавленные типы:
  • password — с minlength.
  • number — с min/max/step.
  • range — с отображением текущего значения (см. раздел extra_js ниже) и output.
  • color — выбор цвета.
  • date/time/datetime-local/week/month — все основные календарные типы.
  • file — accept/multiple/capture (загрузка файлов, в т.ч. с камеры/микрофона на поддерживаемых устройствах).

Многострочное поле (textarea)
- Базовый пример с placeholder.
- Пример с rows/cols для видимых размеров.
- Пример с wrap=hard: переносы строк включаются в отправляемое значение.

Выпадающие списки и переключатели
- Обычный select с обязательным выбором.
- Select с multiple и size для множественного выбора.
- Флажки (checkbox) с обязательным согласием (required) и необязательной подпиской на новости.
- Переключатели (radio) для выбора пола (мужской/женский/другой).
- Select с optgroup для логических групп (Контакты, Другое) — улучшает семантику больших списков.

Список подсказок (datalist)
- Поле ввода с list и соответствующим <datalist>, предлагает значения «Пилинг», «Массаж», «Консультация», «Лазерная эпиляция».
- В отличие от select, пользователь может ввести произвольное значение.

Группировка полей (fieldset/legend) и подсказки
- Пример fieldset с legend «Контактные данные *» и общей подсказкой aria-describedby для всей группы.
- Внутри — два обязательных поля (имя, email) с индивидуальными подсказками (для имени — через aria-describedby на small).

Валидация и ошибки (aria-invalid, role=alert)
- Отдельная форма с novalidate и общим блоком сообщений об ошибках (role=alert).
- Поля email и tel помечены aria-invalid="true" и связаны с сообщениями об ошибках через aria-describedby.
- Демонстрирует, как объявлять ошибки доступно для скринридеров.

Автозаполнение (autocomplete) — расширенные токены
- Имена: given-name/family-name.
- Адрес: address-line1/2.
- Платёжные данные (демонстрация токенов): cc-number, cc-exp.
- Форма содержит autocomplete="on", чтобы браузер мог предлагать автозаполнение.

Разные типы форм
- GET-поиск: форма с method="get" и полем поиска.
- multipart загрузка: форма с enctype="multipart/form-data" для передачи файлов, кнопка отправки.
- Форма с отключёнными autocomplete и novalidate: демонстрирует влияние атрибутов на поведение браузера.

Доступность (ARIA)
- Короткий раздел с рекомендациями: использовать label for/id, aria-describedby, избегать tabindex>0.
- Пример поля «Полное имя *» с aria-required и связанной подсказкой.

Стили (extra_css блока)
- Базовая стилизация контейнеров форм: видимые рамки, фокусное состояние (border-color: var(--primary)), оформление fieldset/legend.

Поведение (extra_js)
- Скрипт для примера range — динамически показывает текущее значение рядом с ползунком (обновление по событию input).
- Это демонстрирует улучшение UX без вмешательства в серверную логику.

Как использовать примеры на практике
- Браузерная валидация (required, pattern, type) — хорошая подсказка, но не заменяет серверную.
- ARIA-атрибуты используйте для доступности: aria-describedby для подсказок/ошибок, aria-invalid для обозначения состояния валидации.
- autocomplete-токены подбирайте по спецификации (name, email, tel, address-line1 и др.) в зависимости от назначения поля.
- Для телефонов и сложных форматов применяйте pattern и при необходимости JS-маску, но на сервер отправляйте нормализованные данные.
